Workflow Engineering with LLM Frameworks

Chaining, State vs Memory, Ingestion Pipelines & Orchestration (LangGraph / LlamaIndex)

Introduction to LLM Workflow

Exam Highlight

What is LLM Workflow? Combining multiple LLM calls, tool usages, and data-processing steps into an organized, automated pipeline rather than relying on a single one-shot prompt.

Problem Statement:

A single prompt call is like an intern with a great memory but no structure. It fails at complex multi-step tasks due to context limits, no memory, and lack of deterministic control.

The 4 Levels of AI Automation:

  1. Level 1 (Prompting): Single Q&A (One-off).
  2. Level 2 (Chaining): Fixed linear steps (Step A → B → C).
  3. Level 3 (Agents): Dynamic loops (Decide → Act → Observe).
  4. Level 4 (Multi-Agent): Autonomous specialized teams.

Chaining & Execution Patterns

Exam Highlight

LLM Chains: Connecting multiple LLMs or their outputs to tools/services where output of step $N$ becomes input to step $N+1$.

Sequential Chain

Linear, fixed-order pipeline. Best for predictable tasks where each step strictly requires previous results (e.g. Summarize → Translate).

Conditional Routing

Dynamic "if-then" branching at runtime based on classification or state (e.g. Refund vs Tech Support route).

State vs. Memory

Exam Highlight
Attribute State Memory
Time Horizon Short-term (current run) Long-term (across sessions)
Purpose Manage current task execution Retain user habits & preferences
Lifecycle Temporary (cleared after run) Persisted intentionally
Example Current pizza order: Large Pepperoni "User always orders Pepperoni"

LangGraph mapping: Short-term state is handled by Checkpointer (thread_id); Long-term memory is handled by Store (namespaces).

Document Ingestion Pipelines

Exam Highlight

4-Stage Ingestion Lifecycle:

1. Loading: Load raw files (PDF, DOCX, CSV) into standardized Document objects with stable IDs.
2. Cache/Hash Check: Docstore checks cryptographic content hash. If file hash matches, skip to avoid expensive embedding recomputation.
3. Transformations: Chunking (SentenceSplitter) → Metadata Extraction (TitleExtractor) → Embedding Generation.
4. Vector Store Save: Persist chunks, metadata, and vectors into vector database (upsert support).

Module 1: RAG Fundamentals

The 5-Stage Pipeline, Embeddings, Chunking Strategies & Vector Databases (ChromaDB)

The RAG Pipeline & Comparison

Exam Highlight

Two Pipelines of RAG:

  • Offline: Ingest → Chunk → Embed → Store in Vector DB (Runs once).
  • Online: Query → Embed Query → Retrieve → Augment → Generate (Every query).
RAG vs Fine-Tuning vs Long-Context:

• RAG: Dynamic, rapidly changing facts, private data, verifiable citations.

• Fine-Tuning: Adapting style, tone, format, and task behavior; NOT for fact injection.

• Long-Context: One-off ad-hoc analysis; high per-token cost on every call, suffers from "Lost in the Middle".

Chunking Strategies & Overlap

Exam Highlight

Fixed-Size

Cuts at exact token/char count; risks slicing mid-sentence.

Recursive

Paragraph → Sentence → Word. Keeps sentences whole.

Semantic

Splits when topic shifts; higher accuracy, costlier.

Chunk Overlap (10–20%, e.g., 50–100 tokens):

Repeats tokens at chunk boundary so sentences cut in half appear completely intact in at least one chunk.

Structure-Aware Splitting: Preserves tables, headers, and code blocks together.

Similarity Search Metrics

Exam Highlight
Cosine Similarity: cos(θ) = (A · B) / (||A|| ||B||)

Measures angle between vectors. Invariant to text length. Values -1 to 1 (or 0 to 1 for normalized vectors).

Dot Product: A · B = Σ A_i * B_i

Measures angle + magnitude. If vectors are unit-normalized, dot product equals cosine similarity and is faster.

Euclidean Distance (L2): d(A, B) = √Σ(A_i - B_i)²

Straight-line distance. Smaller value means closer/higher similarity.

Vector DBs vs Traditional DBs

Exam Highlight

What Vector DB does differently: Traditional DBs use B-trees for exact match queries (WHERE id = 5). Vector DBs use HNSW (Hierarchical Navigable Small World) for sub-millisecond Approximate Nearest Neighbor (ANN) search over 768+ dimensions.

Embedded / Local

ChromaDB in-process. Zero Docker, fastest for ≤ 1M vectors.

Client-Server

Qdrant, Milvus. Microservice, multi-user, payload filters.

Pgvector

Postgres extension. Unified SQL + vector in one table.

Module 2: Advanced RAG Architecture & Evaluation

Hybrid Search, BM25, RRF, Graph RAG, Agentic RAG, Cross-Encoder Reranking & Context Management

Hybrid Retrieval & RRF

Exam Highlight

Two Searches, Two Blind Spots:

  • Dense misses: Exact part numbers (SKU-4471), error codes (E-1147), acronyms (KSHRD).
  • BM25 misses: Synonyms (car vs automobile), paraphrases, cross-lingual queries.

Reciprocal Rank Fusion (RRF) Formula:

RRF(d) = Σ 1 / (k + rank_i(d))

Standard constant k = 60. Discards raw scores and combines strictly by rank position. Agreement wins!

Graph RAG (Microsoft Approach)

Exam Highlight

When chunk retrieval fails: Multi-hop queries (vendor in Chunk 14, supplier in Chunk 902) and global thematic queries (summarize 400 reports).

Graph Construction: Entity Extraction → Relationship Extraction (Triples: (Sokha)-[:MEMBER_OF]->(Platform)) → Neo4j MERGE.

Hierarchical Leiden Algorithm: Partitions the graph into communities; LLM generates summary reports for each cluster.

Local vs Global Search:

• Local: Walks 1–2 hops outward from query entities (fast, specific facts).

• Global: Map-reduce over community summary reports (corpus-wide themes).

Agentic RAG & Self-Reflection

Exam Highlight

What makes RAG "Agentic": The retrieval strategy is chosen dynamically at runtime by the model in a loop (Retrieve → Judge → Rewrite → Retrieve Again), rather than a single fixed pass.

Self-Reflective RAG (3 Critical Checks):

1. Check 1 (Before Generation): Are retrieved chunks relevant? (Filter out non-relevant ones).

2. Check 2 (After Generation): Is the draft answer grounded in context? (Catches hallucination).

3. Check 3 (After Generation): Does the answer address the original question?

Execution Cap: Must have strict stopping conditions (max iterations ≤ 3) to prevent runaway loops.

Cross-Encoders & Context Management

Exam Highlight

Bi-Encoder vs Cross-Encoder:

  • Bi-Encoder (Two Towers): Encodes query and doc separately; fast cosine match; lacks token interaction.
  • Cross-Encoder (Single Tower): Encodes [CLS] query [SEP] doc together; full cross-attention; highly accurate.

Two-Stage Pipeline: Broad recall (top-50 via Hybrid) → Cross-Encoder rerank to top-5.

"Lost in the Middle": Accuracy drops for facts in the middle of prompt. Fix: Reorder chunks (Rank 1 first, Rank 2 last, weakest in the middle).

Autonomous Agents & Tool Integration

Tool Lifecycle, Schemas, Bounded Actions, Agent Patterns, Harness Kernel, MCP Server & HITL

Tool Calling Architecture

Exam Highlight
"The model requests the action; the application executes it."

LLMs have no sockets, DB drivers, or execution runtime. Local models in Ollama emit structured JSON tool calls; the host Python application executes the function and feeds the observation back.

Schema Validation vs Business Validation:

• Schema: Type, shape, required fields ("Is request well-formed?").

• Business: Does record exist? In stock? Has permission? ("Is it okay to do?").

"A valid schema does not guarantee a valid argument (-5 is a valid int, but invalid product ID)."

Bounded Actions & Failure Boundaries

Exam Highlight

Principle of Least Privilege: Never expose eval(), raw shell, or arbitrary SQL strings. Use narrow, parameterized allowlist tools.

Green (Read)

Auto-execute

Yellow (Write)

Audit + Rollback

Red (Destruct)

Human Approval

Failure Boundary: Wrapping calls in error handling so crashes become observations. The agent reads the error and chooses an alternative action instead of crashing the system.

Agent Patterns & Harness Design

Exam Highlight

The 5 Agent Patterns:

• ReAct: Reason + Act + Observe loop. Best for unpredictable, dynamic tasks.

• Router: Classifies request to select single best specialist agent/tool.

• Planner-Executor: Plans steps upfront, executes sequentially, replans on failure.

• Reflection: Generator → Critic → Reviser loop for objective quality gating.

• Multi-Agent: Supervisor delegates specialized subtasks to independent agents.

The Harness OS-Kernel Analogy:

Model = Untrusted CPU (generates tokens). Harness = Kernel (enforces syscalls, permissions, memory boundaries, and budgets).

MCP Server & Human-in-the-Loop

Exam Highlight

MCP (Model Context Protocol): Solves the $M imes N$ integration problem by providing a standardized host/client/server protocol.

3 MCP Primitives: Tools (model-called actions), Resources (readable attachments), Prompts (slash commands).

Lifecycle: Initialization → Operation (tools/list, tools/call) → Shutdown.

HITL vs HOTL vs HOOTL:

• Human-IN-the-loop: Blocks execution until human approves (highest safety).

• Human-ON-the-loop: Runs automatically; streams to audit log with abort/rollback.

• Human-OUT-of-the-loop: Fully autonomous; only post-hoc logging.

Lesson 04

LangGraph: Conditional Edge vs Command & Checkpointing

Python 
from typing import TypedDict, Literal
from langgraph.graph import StateGraph, START, END
from langgraph.checkpoint.memory import InMemorySaver
from langgraph.types import Command

class State(TypedDict):
    ticket: str
    tries: int

# Option A: Conditional Edge routing
def route(state: State) -> str:
    return "billing" if "billing" in state["ticket"].lower() else "general"

# Option B: Command (Modern 1-step route + state update)
def classifier(state: State) -> Command[Literal["billing", "general"]]:
    if "billing" in state["ticket"].lower():
        return Command(update={"tries": state["tries"] + 1}, goto="billing")
    return Command(update={"tries": state["tries"] + 1}, goto="general")

# Short-term thread memory setup
builder = StateGraph(State)
builder.add_node("classifier", classifier)
checkpointer = InMemorySaver()
app = builder.compile(checkpointer=checkpointer)

# Using thread_id for conversation persistence
config = {"configurable": {"thread_id": "session-101"}}
app.invoke({"ticket": "My billing failed", "tries": 0}, config)

Exam Traps & Key Concepts:

1. Conditional Edge vs Command: Conditional edge requires a separate routing function passed to add_conditional_edges(). Command is newer and returns the state update and the next destination (goto) together!

2. Checkpointer Scope: InMemorySaver() scopes by thread_id. Two calls with the same thread_id share state; a different thread_id starts an empty conversation.

3. Volatility Trap: InMemorySaver lives in RAM and is lost upon process exit. For production, use PostgresSaver or SqliteSaver.

Lesson 06

Hybrid Retrieval: BM25 + Dense + Reciprocal Rank Fusion (RRF)

Python 
from rank_bm25 import BM25Okapi

# 1. BM25 Sparse Index
tokens = [c["text"].lower().split() for c in chunks]
bm25 = BM25Okapi(tokens, k1=1.5, b=0.75)

def sparse_search(query, top_n=50):
    scores = bm25.get_scores(query.lower().split())
    order = sorted(range(len(scores)), key=lambda i: -scores[i])
    return [chunks[i]["id"] for i in order[:top_n]]

# 2. Reciprocal Rank Fusion (The whole algorithm)
def fuse(*ranked_lists, k=60, top_k=5):
    fused = {}
    for ids in ranked_lists:
        # NOTE: enumerate must start at 1 (1-based rank)
        for rank, doc_id in enumerate(ids, start=1):
            fused[doc_id] = fused.get(doc_id, 0.0) + 1.0 / (k + rank)
    
    # Sort descending by fused score
    return sorted(fused, key=fused.get, reverse=True)[:top_k]

# Stage 1: Broad Retrieval & Fusion
top5 = fuse(dense_search(q, 50), sparse_search(q, 50))

Exam Traps & Key Concepts:

1. The 1-Based Rank Trap: Look at enumerate(ids, start=1). Ranks must be 1-based ($1, 2, 3...$). Starting at 0 silently distorts all reciprocal scores!

2. Join Key: Both indexes must use the identical chunk ID (e.g. source::chunk_n) to join properly.

3. Discarding Raw Scores: RRF discards cosine distances and BM25 float scores entirely; it uses only positions, avoiding score normalization issues.

Lesson 06

Two-Stage Pipeline & Context Reordering (Lost in the Middle)

Python 
from sentence_transformers import CrossEncoder

# Loaded ONCE at startup (module scope)
reranker = CrossEncoder("BAAI/bge-reranker-base", max_length=512)

def rerank(query, candidates, top_k=5):
    pairs = [(query, c["text"]) for c in candidates]
    scores = reranker.predict(pairs, batch_size=16)
    # Higher is better for CrossEncoder logits
    ranked = sorted(zip(candidates, scores), key=lambda p: p[1], reverse=True)
    return [c for c, _ in ranked[:top_k]]

def reorder_lost_in_middle(picked_chunks):
    # Even/odd split puts Rank 1 first, Rank 2 last, weakest in middle
    head, tail = [], []
    for i, c in enumerate(picked_chunks):
        (head if i % 2 == 0 else tail).append(c)
    return head + tail[::-1]

Exam Traps & Key Concepts:

1. Startup Load Trap: Never initialize CrossEncoder(...) inside the per-query request function! It downloads or instantiates transformer weights, adding seconds of latency.

2. Sorting Direction: reverse=True because Cross-Encoder outputs logits where higher numbers represent higher relevance (unlike ChromaDB distance where lower is closer).

3. Lost in the Middle Fix: Placing Rank 1 at head and Rank 2 at the tail capitalizes on the transformer's primacy and recency attention bias.

Lesson 07

Tool Definition Schema & FastMCP 15-Line Server

Python 
from mcp.server.fastmcp import FastMCP

# Create server instance
mcp = FastMCP("warehouse-service")

# 1. TOOL (Model-controlled action)
@mcp.tool()
def check_stock(product_id: int) -> dict:
    """Check remaining stock for a product ID in inventory."""
    if product_id <= 0:
        return {"error": "Invalid product_id"}
    return {"product_id": product_id, "in_stock": True, "qty": 42}

# 2. RESOURCE (Readable data attachment)
@mcp.resource("inventory://catalog")
def get_catalog() -> str:
    """Read-only catalog data attached like a file."""
    return "SKU-101: Laptop, SKU-102: Monitor"

if __name__ == "__main__":
    mcp.run(transport="stdio")

Exam Traps & Key Concepts:

1. Tool vs Resource: @mcp.tool() is invoked by the model with model-generated arguments. @mcp.resource() is read by the host/user like opening a file.

2. Docstrings Matter: In FastMCP, the docstring and type hints automatically generate the JSON Schema. If you omit the docstring, the model has no description to know when to route to it!

3. stdio Transport: stdio connects via local subprocess streams. Its lifecycle is tied directly to the parent application process.

Lesson 06 — Exam Highlight

Neo4j Cypher Scripting: Triple Creation & Multi-Hop Traversal

Cypher 
// 1. BASIC TRIPLE CREATION (THE EXAM SCRIPT)
CREATE (a:Entity {name: "Sokha"})-[r:WORKS_ON]->(b:Entity {name: "Invoicing Service"})
RETURN a, r, b;

// 2. IDEMPOTENT LOADING (Slide 29: Always MERGE, never CREATE)
MERGE (a:Person {name: "Sokha"})
MERGE (b:Service {name: "Invoicing Service"})
MERGE (a)-[r:OWNS]->(b)
SET r.chunk_id = "handbook::chunk_12", r.weight = 8
RETURN a, r, b;

// 3. ONE-HOP MATCHING
MATCH (p:Person {name: "Sokha"})-[:MEMBER_OF]->(t:Team)
RETURN t.name;

// 4. MULTI-HOP GRAPH RAG TRAVERSAL (Service <- OWNS - Person - MEMBER_OF -> Team)
MATCH (s:Service {name: "Billing"})<-[:OWNS]-(p:Person)-[:MEMBER_OF]->(t:Team)
RETURN p.name AS owner, t.name AS team;

// 5. VARIABLE-LENGTH BOUNDED PATH TRAVERSAL (1 to 3 hops)
MATCH path = (a:Entity {name: "LegacyPay"})-[*1..3]-(b:Entity)
RETURN path
LIMIT 25;

// 6. SAFE NODE DELETION
MATCH (a:Entity {name: "Sokha"})
DETACH DELETE a;

Exam Traps & Key Concepts:

1. CREATE vs MERGE: CREATE is NOT idempotent. Running it twice gives you duplicate nodes and duplicate edges. MERGE finds or creates, preventing graph duplication.

2. Directed Edges: (a)-[r:WORKS_ON]->(b) specifies directed relationship from a to b. Arrow direction determines semantic meaning.

3. DETACH DELETE: Running DELETE a on a node with connected relationships throws an error. Use DETACH DELETE a to safely delete connected relationships first.

4. Bound Traversals: Never run unbounded [*]; always cap depth with [*1..3] and LIMIT to prevent exponential path search freezing the server.
